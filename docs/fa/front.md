# عبور از کلودفلر (حالت Front)

بعضی وقت‌ها ارتباط مستقیم بین سرور ایران (Hub) و سرور خارج (Node) فیلتر می‌شود. معمولاً اتصال برقرار می‌شود و بعد از چند تبادل وسط راه قطع می‌شود. در این حالت با هیچ تانل مستقیمی نمی‌شود این دو سرور را به هم وصل کرد.

حالت Front، Hub را پشت یک رکورد کلودفلر می‌گذارد. Node دیگر مستقیم به IP سرور ایران وصل نمی‌شود، بلکه به کلودفلر وصل می‌شود و کلودفلر اتصال را به Hub می‌رساند. یعنی:

- کانال کنترل از کلودفلر رد می‌شود (وضعیت، دستورها، آپدیت).
- **ترافیک تانل** هم از کلودفلر رد می‌شود (همان چیزی که کاربران شما رد و بدل می‌کنند).
- کاربران شما هیچ تغییری نمی‌بینند و همچنان به IP و پورت سرور ایران وصل می‌شوند.

```
کاربر ──► Hub (ایران) ◄── کلودفلر ◄── Node (خارج) ──► سرویس VPN
```

کلودفلر فقط داده‌های رمزشده را می‌بیند. داخل اتصال یک لایهٔ TLS جداگانه هست که فقط Hub و Node آن را باز می‌کنند.

## چه چیزهایی لازم است

- یک دامنه که در کلودفلر است (پلن رایگان کافی است).
- نسخهٔ 0.3.0 یا بالاتر روی هر دو سرور (`deyroute update`).

## ۱) تنظیم کلودفلر (فقط یک بار)

1. **DNS**: یک رکورد `A` بسازید، مثلاً `t1`، که به **IP سرور ایران** اشاره کند. ابر نارنجی (**Proxied**) را روشن کنید.
2. **SSL/TLS → Overview**: حالت را روی **Full** بگذارید.
3. **Network**: گزینهٔ **WebSockets** را روشن کنید.

## ۲) روی سرور ایران

```bash
deyroute front enable --domain t1.example.com
```

`t1.example.com` را با رکوردی که ساختید عوض کنید. این دستور Front را روی پورت `2053` روشن می‌کند (یکی از پورت‌هایی که کلودفلر عبور می‌دهد) و در آخر چیزی شبیه این نشان می‌دهد:

```
Cloudflare front: on · t1.example.com:2053 · listening · tls auto
...
On each node that should go through Cloudflare, run (keep it private, it holds the front's secret path):
   deyroute node set-hub 'wss://t1.example.com:2053/...'
```

هر وقت خواستید دوباره ببینید:

```bash
deyroute front status
```

## ۳) روی سرور خارج

همان خطی را که سرور ایران نشان داد، روی سرور خارج اجرا کنید:

```bash
deyroute node set-hub 'wss://t1.example.com:2053/...'
```

Node از همین لحظه از کلودفلر وصل می‌شود. تانل‌هایش خودکار دوباره ساخته می‌شوند تا از کلودفلر رد شوند. لازم نیست کاری دیگر بکنید و تانل یا Join را هم دوباره نمی‌سازید.

**Node جدید:** وقتی Front روشن است، `deyroute node join-command` لینکی می‌دهد که خود Join هم از کلودفلر انجام می‌شود.

## ۴) بررسی

روی سرور ایران:

```bash
deyroute status
```

- جلوی Node عبارت `via front` را می‌بینید.
- تانل `UP` است.

## چه ترنسپورت‌هایی از کلودفلر رد می‌شوند

فقط ترنسپورت‌هایی که در آن‌ها Node با TCP به Hub وصل می‌شود:

- Backhaul (`tcp`، `tcpmux`، `ws`، `wsmux`، `wssmux`)
- rathole
- FRP (`tcp`، `websocket`)
- chisel و gost

بقیه برای Nodeی که از کلودفلر وصل است کنار گذاشته می‌شوند (کد `DEY-B012`). موتور Failover خودش پلهٔ بعدی را برمی‌دارد:

- آن‌هایی که UDP لازم دارند (Hysteria2، WireGuard، `backhaul/udp`)
- آن‌هایی که Hub مستقیم به Node وصل می‌شود (`xray/reality`، `direct/native`)
- Waterwall، چون IP واقعی Node را چک می‌کند
- در تانلی که هم TCP و هم UDP دارد، ترنسپورت‌هایی که برای UDP یک فرایند جدا لازم دارند

## سرعت و پایداری

- **سرعت:** تأخیر کمی بیشتر می‌شود، چون هر بسته از دیتاسنتر کلودفلر رد می‌شود. پلن رایگان برای VPN کافی است.
- **قطعی کلودفلر:** اگر اتصال کلودفلر قطع شود، Node خودش دوباره وصل می‌شود. تانل هم بعد از وصل شدن دوباره خودکار بالا می‌آید.
- **فایروال:** پورت Front در فایروال Hub فقط به روی IPهای کلودفلر باز است. هر کس دیگری که پورت را باز کند، یک صفحهٔ وب معمولی می‌بیند. مسیر مخفی فقط جلوی اسکنرها را می‌گیرد و امنیت اصلی را TLS داخلی تأمین می‌کند.

## برگشتن به اتصال مستقیم

اگر مسیر مستقیم دوباره باز شد، روی سرور خارج:

```bash
deyroute node set-hub IP_سرور_ایران:44433
```

برای خاموش کردن Front روی سرور ایران:

```bash
deyroute front disable
```

این دستور Nodeهایی را که از Front استفاده می‌کردند نام می‌برد، با دستوری که هر کدام را به مسیر مستقیم برمی‌گرداند.

## پورت دیگر

پورت پیش‌فرض `2053` است. می‌توانید هر کدام از پورت‌هایی را که کلودفلر عبور می‌دهد انتخاب کنید:

| نوع | پورت‌ها | حالت SSL در کلودفلر |
| --- | --- | --- |
| HTTPS | `2053`، `2083`، `2087`، `2096`، `8443` | **Full** |
| HTTP | `8080`، `8880`، `2052`، `2082`، `2086`، `2095` | (فرقی نمی‌کند) |

```bash
deyroute front enable --domain t1.example.com --port 8443
```

پورت 443 را برای تانل‌ها نگه دارید.

## خطاهای رایج

| کد | معنی | راه‌حل |
| --- | --- | --- |
| `DEY-N016` | Node به کلودفلر نمی‌رسد (DNS، TLS، ساعت سرور) | رکورد DNS و ابر نارنجی را چک کنید؛ ساعت سرور خارج درست باشد |
| `DEY-N017` با 522 | کلودفلر به Hub نمی‌رسد | IP رکورد باید IP سرور ایران باشد؛ `deyroute front status` باید `listening` نشان دهد؛ پورت در پنل شرکت سرور ایران باز باشد |
| `DEY-N017` با 400/426 | WebSockets در کلودفلر خاموش است | Network → WebSockets را روشن کنید |
| `DEY-N017` با 525/526 | حالت SSL اشتباه است | برای پورت‌های HTTPS حالت **Full** بگذارید |
| `DEY-N018` | Hub اتصال تانل را رد کرد | تانل را با `deyroute tunnel restart <tunnel>` دوباره راه بیندازید؛ ساعت دو سرور بیش از ۲ دقیقه اختلاف نداشته باشد |
| `DEY-B012` | این پله از کلودفلر رد نمی‌شود | کاری لازم نیست؛ پلهٔ بعدی استفاده می‌شود |
