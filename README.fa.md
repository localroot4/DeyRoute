## DEYROUTE چیست؟

DEYROUTE دو نوع سرور را به هم وصل می‌کند:

- **هاب (Hub):** سرور شما **در ایران**. کاربرانتان فقط به همین وصل می‌شوند.
- **نود (Node):** سرور یا سرورهای شما **در خارج**. سرویس واقعی VPN شما (Xray، Marzban، 3x-ui و مانند آن) روی آن‌هاست.

</div>

```text
  کاربران                    HUB (ایران)                        NODE (خارج)
  ┌────────┐   HUB_IP:443   ┌──────────────┐     تانل        ┌──────────────────┐
  │ موبایل │ ─────────────▶ │  deyroute hub  │ ═══════════════▶│  deyroute node     │ ──▶ Xray / Marzban
  │ لپ‌تاپ │                └──────────────┘                 │  سرویس VPN شما   │     3x-ui ...
  └────────┘                       ▲                         └──────────────────┘
                                   └─ اگر این نود از کار بیفتد، نود پشتیبان خودکار جایش را می‌گیرد
```

<div dir="rtl">

کاربران هرگز آدرس سرور خارج را نمی‌بینند. ترافیکشان همان‌طور که از دستگاهشان
خارج شده از تانل می‌گذرد: DEYROUTE آن را باز نمی‌کند، تغییر نمی‌دهد و دوباره رمز نمی‌کند.

## چرا DEYROUTE؟

| | |
| --- | --- |
| **سه قدم، فقط کپی و پیست** | روی هاب نصب کنید، یک خط را روی نود بچسبانید، تانل را بسازید. هر سؤال یک جواب پیشنهادی دارد: برای قبولش فقط <kbd>Enter</kbd> بزنید. |
| **شناسایی‌اش سخت است** | هشت روش تانل از برنامه‌های مختلف، از جمله روش‌هایی که شبیه HTTPS معمولی به یک سایت واقعی‌اند. وقتی یکی شناسایی و بسته شود، بعدی شروع می‌شود. |
| **خودش را درست می‌کند** | هاب هر تانل را چند بار در دقیقه آزمایش می‌کند. روش بسته‌شده معمولاً ظرف ۳۵ ثانیه عوض می‌شود، بدون اینکه کسی بیدار باشد. وقتی روش اول دوباره کار کرد، تانل به آن برمی‌گردد. |
| **نود پشتیبان** | یک سرور خارج دیگر اضافه کنید؛ اگر اولی از کار بیفتد، تانل خودش به آن می‌رود. |
| **سرویس شما همان‌طور می‌ماند** | همان پورت، همان گواهی، همان UUID. در تنظیمات کلاینت فقط آدرس سرور عوض می‌شود، به IP هاب. |
| **خطاهایی که می‌شود خواند** | هر مشکل می‌گوید چه شد، چرا شد و چه کنید، با یک کد ثابت مثل `DEY-P012`. |
| **ساخته‌شده برای حریم خصوصی** | یک برنامهٔ امضاشده، بدون ارسال هیچ آماری، بدون راز در لاگ‌ها، و دقیقاً یک جدول فایروال که فقط DEYROUTE آن را مدیریت می‌کند. |

## شروع سریع (۵ دقیقه)

**چه چیزهایی لازم است:** یک سرور در ایران (هاب)، یک سرور خارج که سرویس VPN شما
از قبل روی آن کار می‌کند (نود)، و دسترسی `root` روی هر دو. Ubuntu 22.04 / 24.04 / 26.04
یا Debian 12 / 13 با معماری amd64 یا arm64. چیز دیگری نمی‌خواهد: نه Python، نه Docker.

### ۱. روی هاب (سرور ایران)

</div>

```bash
bash <(curl -fsSL https://github.com/localroot4/DeyRoute/releases/latest/download/install.sh)
```

<div dir="rtl">

یک ویزارد کوتاه پنج سؤال می‌پرسد، هر سؤال در یک صفحه. برای نقش `1` (هاب) را بزنید،
یک اسم مثل `ir-1` بدهید و برای بقیه فقط <kbd>Enter</kbd> بزنید. در پایان یک **دستور join**
چاپ می‌شود. کل آن یک خط را کپی کنید.

### ۲. روی نود (سرور خارج)

آن دستور را بچسبانید. فقط یک‌بار قابل استفاده است و ۱۵ دقیقه اعتبار دارد:

</div>

```bash
bash <(curl -fsSL https://github.com/localroot4/DeyRoute/releases/latest/download/install.sh) join 'dey://…'
```

<div dir="rtl">

حدود ۳۰ ثانیه بعد نود روی هاب دیده می‌شود:

</div>

```bash
deyroute node list
```

<div dir="rtl">

### ۳. روی هاب: تانل را بسازید

شناسهٔ نودی را که `deyroute node list` نشان داد و پورتی را که سرویس VPN شما استفاده می‌کند بنویسید:

</div>

```bash
deyroute tunnel add --node de-1 --ports 443
```

<div dir="rtl">

مرحله‌ها را می‌بینید که رد می‌شوند و آخرش خطی مثل این می‌آید:

</div>

```text
✔ Tunnel main is UP via backhaul/wssmux (41ms)
```

<div dir="rtl">

### ۴. بررسی کنید، بعد آدرس را در کلاینت‌ها عوض کنید

</div>

```bash
deyroute status
deyroute port check 443
```

<div dir="rtl">

در تنظیمات کلاینت‌ها آدرس نود را با **IP هاب** عوض کنید. همهٔ چیزهای دیگر (پورت،
UUID، SNI، مسیر) را دقیقاً مثل قبل نگه دارید. تمام.

> **قدم بعدی که توصیه می‌شود:** یک سرور خارج دیگر هم به همین روش اضافه کنید و آن را
> پشتیبان کنید: `deyroute tunnel backup add main --node nl-1`

## کار روزمره

با تایپ `deyroute` (یا فقط `dey`) منو باز می‌شود. یک شماره بزنید و <kbd>Enter</kbd>.
<kbd>q</kbd> برمی‌گردد و <kbd>?</kbd> صفحه‌ای را که در آن هستید توضیح می‌دهد.

</div>

```text
 1) Dashboard       4) Ports           7) Optimize         10) Backup & Restore
 2) Tunnels         5) Failover        8) Security         11) Update
 3) Nodes           6) Diagnostics     9) Notifications    12) Settings
```

<div dir="rtl">

هر کاری که منو می‌کند با دستور هم ممکن است، برای اسکریپت‌ها (با `--json`):

| می‌خواهم… | این را بزنم |
| --- | --- |
| همه‌چیز را یک‌جا ببینم | `deyroute status` |
| یک سرور خارج اضافه کنم | `deyroute node join-command` (روی هاب)، بعد خط را روی سرور جدید بچسبانم |
| تانل بسازم | `deyroute tunnel add --node de-1 --ports 443,2053` |
| پورت اضافه یا حذف کنم | `deyroute port add main 8443` / `deyroute port remove main 8443` |
| ببینم پورت واقعاً کار می‌کند | `deyroute port check 443` |
| لاگ را زنده ببینم | `deyroute logs main -f` |
| روش یا نود را دستی عوض کنم | `deyroute tunnel switch main --transport backhaul/tcpmux` |
| نود پشتیبان اضافه کنم | `deyroute tunnel backup add main --node nl-1` |
| همهٔ روش‌ها را آزمایش و سرعتشان را مقایسه کنم | `deyroute tunnel test-ladder main` |
| هشدار در تلگرام بگیرم | منوی `9) Notifications` |
| گزارش برای پشتیبانی بگیرم | `deyroute doctor` (رازها حذف می‌شوند) |

تازه‌کارید؟ در **حالت Simple** بمانید: همهٔ بخش‌های پیشرفته را پنهان می‌کند و برای هر کار
حداکثر سه سؤال می‌پرسد. هر وقت بیشتر خواستید، از `12) Settings ← UI mode` عوضش کنید.

## مقابله با فیلترینگ

فیلترینگ مدام عوض می‌شود، پس یک روش هیچ‌وقت کافی نیست. هر تانل یک **نردبان** از
روش‌های برنامه‌های مختلف دارد. یک پله ترافیک را می‌برد و بقیه نصب و آماده‌اند و منتظرند.

| پله | روش | چرا هست |
| :-: | --- | --- |
| ۱ | `backhaul/wssmux` | TLS و WebSocket با اتصال‌های کم؛ شبیه HTTPS معمولی |
| ۲ | `backhaul/tcpmux` | بدون لایهٔ TLS و با کمترین سربار؛ برای وقتی که خودِ TLS تانل دیده می‌شود |
| ۳ | `rathole/noise` | برنامه و پروتکل دیگر با رمزنگاری Noise |
| ۴ | `frp/tcp` | برنامهٔ سوم با الگوی ترافیک متفاوت |
| ۵ | `xray/reality` | شبیه بازدید واقعی TLS 1.3 از یک سایت بی‌خطر |
| ۶ | `hysteria2/udp` | QUIC؛ روی خطوط پرافت از همه سریع‌تر، وقتی UDP باز است |
| ۷ | `waterwall/reverse-reality` | اتصال معکوس که آن هم شبیه یک سایت واقعی است |
| ۸ | `direct/native` | بدون پنهان‌کاری؛ فقط برای اینکه سرویس از کار نیفتد |

وقتی هاب تأیید کند که پلهٔ فعال بسته شده، پلهٔ بعدی را بالا می‌آورد؛ کاربران معمولاً
متوجه نمی‌شوند. وقتی پلهٔ اول درست شد، تانل برمی‌گردد. ترتیب نردبان را از منو
(`5) Failover`) یا با `deyroute ladder` عوض کنید یا نردبان خودتان را بسازید. جزئیات:
[پرسش‌های فیلترینگ](docs/fa/faq-filtering.md).

**عادت‌های خوبی که سرورهایتان را از رادار دور نگه می‌دارد**

- فقط آدرس هاب را به کاربران بدهید. IP سرور خارج را هرگز منتشر نکنید.
- تنظیمات TLS خود سرویستان (Reality، WebSocket و غیره) را نگه دارید. DEYROUTE جایگزینشان نمی‌شود، آن‌ها را حمل می‌کند.
- برای پله‌های Reality سه سایت طعمه تعیین کنید: `deyroute config edit` و بعد `hub.decoy_snis`.
- یک نود پشتیبان در سرویس‌دهنده یا کشور دیگر نگه دارید.
- هیچ ابزاری نمی‌تواند نامرئی بودن را تضمین کند. کار DEYROUTE این است که شناسایی و مسدود کردنتان را گران کند و وقتی اتفاق افتاد سریع برگردد.

## امنیت

- سرورهای خارج همیشه **به سمت هاب** وصل می‌شوند، با TLS 1.3 دوطرفه و یک CA خصوصی. هاب هرگز به نود لاگین نمی‌کند و از SSH استفاده نمی‌شود.
- خط join فقط **یک‌بار** کار می‌کند و ۱۵ دقیقه بعد منقضی می‌شود.
- DEYROUTE دقیقاً یک جدول فایروال (`inet deyroute`) می‌سازد و مدیریت می‌کند و به بقیهٔ قانون‌های شما دست نمی‌زند.
- هر نسخه امضا می‌شود؛ نصب‌کننده قبل از نصب امضا و چک‌سام را بررسی می‌کند.
- بدون ارسال هیچ آماری. رازها با دسترسی `0600` ذخیره می‌شوند و هرگز در لاگ نمی‌آیند.

بیشتر: [راهنمای امنیت](docs/fa/security.md).

## مشکلی پیش آمده؟

اول `deyroute doctor` را بزنید. سیستم، پورت‌ها، گواهی‌ها، سرویس‌ها و لاگ‌ها را بررسی
می‌کند و هر یافته را با زبان ساده توضیح می‌دهد.

| نشانه | این را امتحان کنید |
| --- | --- |
| نود `offline` است | `deyroute node test <id>`، بعد پورت کنترل 44433 را در فایروال سرویس‌دهنده بررسی کنید |
| تانل `UP` است ولی کلاینت وصل نمی‌شود | `deyroute port check <port>`؛ فایروال سرویس‌دهنده اغلب پورت هاب را می‌بندد |
| تانل مدام روش عوض می‌کند | `deyroute logs <tunnel>` و `deyroute tunnel test-ladder <tunnel>` |
| خطا با یک کد | سه خط آن را بخوانید (چه شد / چرا / راه‌حل)؛ همهٔ کدها در [docs/ERRORS.md](docs/ERRORS.md) است |

بیشتر: [عیب‌یابی](docs/fa/troubleshooting.md).

## خوب است بدانید

- **هاب و نود یک برنامه‌اند.** نقش در ویزارد انتخاب می‌شود.
- **به TLS شما دست زده نمی‌شود.** تانل بایت‌های خام را حمل می‌کند، پس کلاینت شما SNI، مسیر، UUID و اثرانگشتش را نگه می‌دارد.
- **دو سرور باید به هم برسند.** اگر شبکهٔ بین دو کشور مسیر مستقیم را ببُرد، یک Issue باز کنید؛ راهی برای دور زدن آن در حال ساخت است.
- **نسخه‌های توسعه.** نسخه‌ها فعلاً از نوع `edge` هستند و با systemd و nftables واقعی و همهٔ بک‌اندها آزمایش شده‌اند ([شواهد پذیرش](docs/en/acceptance.md)). اجرای دوبارهٔ خط نصب در همان‌جا ارتقا می‌دهد و تنظیمات را نگه می‌دارد.
